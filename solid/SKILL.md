## Principles

S - Single-Responsibility Principle: A class should have only one reason to change
O - Open-Closed Principle: Software entities (classes, modules, functions, etc.) should be open for extension, but closed for modification
L - Liskov's Substitution Principle: Derived or child classes must be able to replace their base or parent classes
I - Interface Segregation Principle: Clients should not be forced to depend on methods that are irrelevant to them
D - Dependency Inversion Principle: High-level modules should not depend on low-level modules. Both should depend on abstractions
